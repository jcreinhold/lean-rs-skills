# On Writing Well

State the point early. Use concrete nouns and strong verbs. Cut hedges, filler, repeated claims, and explanations of what the reader can already see. Use a short common word when it says the same thing. Break a rule when the result would read worse.

## Documentation

- Title by the reader's task.
- Show the common path before detail.
- Explain constraints, choices, and failure cases; do not restate code.
- Keep terms and names consistent.
- Put important limits and gotchas before the reader can misuse the API.
- Use concrete examples and load advanced detail only when needed.

## Comments

Write interface comments for callers and implementation comments for future maintainers. Record invariants, reasons, and surprising behavior. Update or remove a comment when the code changes.
